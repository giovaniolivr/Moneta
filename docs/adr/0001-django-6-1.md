# ADR 0001 — Django 6.1 em vez de 5.2 LTS

- Status: aceita
- Data: 2026-10-11

## Contexto
Critérios pedidos: mais recursos, segurança e previsibilidade. Opções em out/2026:
Django 5.2 LTS (suporte até abr/2028) e Django 6.1 (estável atual, suporte até ~dez/2027).
O próximo LTS, 6.2, sai em abr/2027.

## Decisão
Usar **Django 6.1** (`django>=6.1,<6.2`) e migrar para **6.2 LTS** quando lançado.

Ganhos concretos sobre 5.2 para este projeto:
- **CSP nativo** (`ContentSecurityPolicyMiddleware`, `SECURE_CSP`) — segurança sem dependência extra.
- **Template partials nativos** (`{% partialdef %}`) — o padrão de HTMX (devolver um trecho da
  página) sem pacote de terceiros.
- **Framework de tasks** nativo — base para backups agendados e coletores de preço futuros.

## Previsibilidade da atualização
- Versão fixada no `pyproject.toml` com teto da série (`<6.2`) e `uv.lock` versionado.
- Os testes tratam `DeprecationWarning`/`PendingDeprecationWarning` do Django como **erro**, então
  qualquer API que vá sumir na próxima versão quebra o CI antes da migração.
- Sem dependências que acessem internals do Django.
- Migração 6.1 → 6.2 = subir o teto, `uv lock --upgrade-package django`, rodar a suíte.

## Consequências
Janela de suporte menor que a do 5.2 até a 6.2 sair; aceitável porque a atualização entre
versões consecutivas é pequena e protegida pelos testes.
